# 推理路径盲审：先核实“推理真的变好了吗”

这是第一轮小规模检查，不是已经完成的人工评测。两位审阅者分别填写自己的 CSV（表格文件），先独立判断，再讨论分歧。
如果只有一位审阅者，只能写“单人初审”；AI 的判断也必须单独标记，不能冒充人工结论。

## 先看什么

打开 `题册.md`，填写 `审阅者1.csv` 或 `审阅者2.csv`。**不要打开 `private` 目录**：它保存方案身份和自动分数，等标签固定后再揭晓。
给外部审阅者只发题册、说明和一份空表，不发 private。这里的隐藏用于减少先入为主，不是保密或访问权限控制。

每题有甲、乙两个方案，每个方案保留全部候选答案和路径。甲乙顺序逐题随机；它们不代表固定的方法。
不要因为某个候选看起来好就跳过其他候选，也不要把不同候选拼成一条它们没有实际给出的推理。
题面、实体和原始关系名称保留英文以免翻译改变题意；下面是中文判断指南。

## 每一行怎么填

| 表格列 | 填法 |
|---|---|
| case_id / side / candidate | 题号 / 甲乙 / 候选编号，已经填好，不改 |
| answer_correct | 答案是否正确：填 `是`、`否` 或 `不确定`。核对实际含义，不能只看字符串包含关系；不要无条件相信题库参考答案 |
| path_sufficient | 这条路径能否充分支持它给出的答案：填 `是`、`否` 或 `不确定`。它是独立问题，不要只因答案碰巧对就填“是” |
| error_tags | 可多选，用分号分开：`无明显问题`、`方向错误`、`缺条件`、`缺比较`、`类别枚举`、`终点答案不一致`、`事实不支持`、`疑似标注问题`、`证据不足`、`其他` |
| reason | 用一句中文写关键理由；有错误指出哪一步、有疑问指出缺什么证据。不要只写“看起来对” |

## “路径充分”到底是什么意思

- **实体**就是人、地点、作品等具体对象；**关系**就是对象之间的事实。例如“导演 → 执导 → 电影”。一条箭头走一步，多步连起来就是路径。
- **方向**要按关系含义理解。“某电影由某人导演”和“某人执导某电影”可以是同一事实；不能因为关系名字不同就判错，也不能因为图中能反向走就认定语义成立。
- **缺条件**：题目问“出生在法国、又获得某奖的人”，路径只说明出生地，没说明获奖。这条路径不足以支持完整回答，即使名字恰好答对。
- **缺比较**：问“最后一次”“人口最多”“1971 年之前”，仅列出一个事件、城市或日期通常不够。要有支持筛选或比较的证据；无法核实时记“不确定”，明确缺什么。
- **类别枚举**：问某国首都，却从“城市”这个大类随便走到一个城市。它证明了类别归属，没回答问题所要求的关系。
- **终点答案不一致**：路径最后到达甲，答案却写乙，需要解释两者是否同义。不能因为答案对就忽略断裂。
- **SPARQL**是题库用来查标准答案的程序，像一张条件清单。原始查询用于帮助发现多条件、日期和最高级；不要求你运行它，也不把它视为绝对正确。
- **子图**是每题配的一小块事实网。题册只列出了路径相邻节点之间的原始事实，未列出的事实不等于不存在。`m.xxx` 一类代码是实体编号，不一定是人名，也可能是用于连接复杂事实的中间节点；辨认不了就记证据不足。

判断严格但不凭空挑错：一条正确、完整的替代推理可以通过，不要求它逐字复现标准查询。
正确答案有多种时，本轮检查这个候选是否为其中一个合法答案；答案集合是否完整是另外的问题。

## 抽样约定（看标签之前固定）

1. WebQSP 和 CWQ 各 40 题，共 80 题。每题先随机选一个训练版本（42、43、44），再按该版本的自动分数分组，避免专挑修复有效的版本。
2. 每个题库四组各抽 10 题：修复后才通过、修复前才通过、两边都通过、两边都没通过。分组及身份只保存在 private。
3. 每个题库内部，同一道原题派生出的题只取一道。WebQSP 与 CWQ 之间仍可能共享原题，不应把两个题库简单拼成 80 个独立统计单位。
4. 这是为发现评分漏洞而做的等额分组抽样，各组在全题库中的比例并不相等。**不能拿这 80 题的简单平均估计全题库提升**；去除同族题也改变了抽中机会，不能直接套简单分组权重。
5. 审完再揭晓甲乙，逐组报告自动评分与人工判断的分歧、方向和典型原因。两人分歧先保留并统计，再协商；证据不足单列，不强行当错或当对。
6. 一个方案在人工口径下“答对且路径充分”，要求至少一个**同一候选**的两列都为“是”。这比当前自动关系集合检查更严格，二者差异是本轮要检验的对象。

## 本轮之后怎么决定

- 如果自动判为改善的题，人工也经常确认完整推理改善：保留训练路径修复主线，下一步设计代表性样本并在更接近原论文的设置上验证。
- 如果提升主要来自缺条件、类型捷径或比较约束没检查：先修指标，再重算现有预测；不用先花 GPU 时间重训。
- 如果大批题因为资料不全无法判断：补齐事实与标注证据，再作结论。不能把“无法审”写成“方法无效”。

## 重新生成（给执行脚本的人）

在仓库根目录执行，使用已有 CPU 依赖，不需要 GPU：

```bash
uv run --no-project --python 3.11 --with scikit-learn --with pyarrow --with networkx --with datasets --with transformers python gcr-lab/experiments/build_blind_review.py --output gcr-lab/out/blind_review_2026-11-08
```

输出目录已存在时脚本会停止，避免覆盖人工标签。另选一个新目录可重建。
固定抽样随机数和输入文件后样本可复现；private 内记录 Git 版本、输入与评分器文件的 SHA-256（文件指纹）。
